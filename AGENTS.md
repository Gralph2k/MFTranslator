# Проект: тренажёр эмоционального интеллекта

Telegram-бот, в котором пользователь переписывается с персонажем и получает разбор
своих ходов. Стек: Python 3.13, aiogram 3, SQLite, DeepSeek API.

## Скилы проекта

Проектные скилы лежат в `.dsh/skills/` и видны только при работе в этой папке:

- `writing-scenarios` — как писать и проверять сценарии: психологическая рамка,
  схема файла, контракт, красные флаги. **Читать перед любым новым сценарием.**

## Правила

- Сценарии — данные в `scenarios/<id>/scenario.json`, код их не знает по именам.
  Личность героини — `heroines/<slug>/heroine.json` (имя, возраст, профессия,
  характер, голос, анкета); сценарий ссылается на неё полем `heroine`. Фотографии
  сцены лежат рядом, в `scenarios/<id>/images/`.
- Контракт сценария и героини проверяется `tests/test_scenarios_contract.py`:
  6 пунктов рубрики, `turn_limit` 8–12, стартовая открытость ≤ 0.25, у каждой
  ловушки — объяснение, у включённого сценария есть героиня.
- Сценарий пишется с точки зрения практикующего семейного психолога: сначала навык
  и защитный механизм, потом реплики.
- Секреты и токены — только в `.env`; файл в `.gitignore`.
- **Пуш в GitHub — только по явной команде владельца.** Коммиты локально можно,
  `git push` — никогда без просьбы.
- **Любое изменение кода, сценариев или конфигурации деплоится на VPS и перезапускает
  бота.** «Локально работает» не значит «работает у пользователей»: боевой сервер —
  `root@48.102.186.191`, код в `/opt/mf-translator`, сервис `emotion-trainer`.
  Порядок обязателен: тесты → архив → `chown` → `pip install -e .` →
  `systemctl restart emotion-trainer` → проверка `systemctl is-active` и
  `journalctl -u emotion-trainer` (`Бот запущен`, `Run polling`, без `Traceback`
  и `Conflict`). Команды — `deploy/DEPLOY.md`, §7. `.env` и `data/bot.db` на сервере
  не перезаписываются (в архив не попадают), перед обновлением — бэкап
  `deploy/backup.sh`.
- Перед сдачей: `python -m pytest -q` и прогон `python -m bot.cli --provider demo --scenario <id>`.
