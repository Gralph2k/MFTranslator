---
description: Прогнать pytest в .venv и показать итог — обязательный шаг перед сдачей изменений
argument-hint: [путь или фильтр pytest, например tests/test_eva.py]
---

Прогони тесты проекта из корня `C:\Projects\MFTranslator` и отчитайся фактами.

1. Выполни (Git Bash):

   ```bash
   PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m pytest -q $ARGUMENTS
   ```

   Если `$ARGUMENTS` пустой — просто `-q`. Префикс `PYTHONIOENCODING=utf-8` нужен,
   чтобы кириллица в выводе не ломалась (в Git Bash пайп использует OEM-кодировку).

2. Смотри хвост вывода (последние ~40 строк), а не весь дамп. Baseline на
   10.11.2026 — **216 passed, ~3.5 с**. Резкое расхождение по числу — повод
   разобраться, а не игнорировать.

3. Если есть падения:
   - назови упавшие тесты и первую строку ошибки (`файл:строка`);
   - прочитай тест и код, найди причину;
   - чини причину, а не ожидание теста. Не удаляй тесты, не ставь `skip`/`xfail`
     и не меняй `addopts` в `pyproject.toml` (кэш pytest отключён специально:
     `%TEMP%` в среде разработки был закрыт) без явной просьбы.

4. Тесты не ходят в сеть и не читают `.env`: модель подменяется `FakeLLM`, база —
   временным файлом. Если тест «требует ключ» — это баг теста, а не повод читать
   `.env`.

5. Повтори прогон после правок и отчитайся: команда, `N passed`/`N failed`,
   exit code. Если тесты падают — изменение не готово к сдаче и к деплою.
